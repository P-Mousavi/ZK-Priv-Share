# Comparative implementation audit

The audited History-Hiding revision is `2a109868533d7dd92737bc3911b108a9559e5b38` on `History-Hiding`. Every new benchmark run records HEAD, working-tree status, source hashes, artifact hashes, compiler settings and host/tool versions. Benchmark additions may be uncommitted; the measurements identify the actual protocol source files rather than assuming HEAD alone describes the working tree.

The original non-ZK baseline is available in local Git history at `df954fd862862e65a2e66af3a18d1526d78bfd7e` (initial proof-of-concept). Its `contracts/Identity.sol:IdentityContract` and `contracts/data.sol:DataContract` are compiled directly from that revision. This is the repository's original Priv-Share implementation, not a claim that it is an independently authenticated upstream implementation of every feature in the reference paper. No baseline is reconstructed or fetched. The original contracts have no imports, libraries, Merkle trees or Groth16 verifiers. The baseline deploys IdentityContract and DataContract and initializes their authorization link separately. Registration requires a 1 ETH deposit; CTI publication stores CIDs, fees and delegates; access uses addresses and credentials; disputes use manager voting; slashing and rewards perform direct payments.

The current IdentityContract is unsuitable as the original baseline: subsequent revisions added IdentityTree, linked Poseidon/Merkle libraries and a testingMode that can omit registration storage. DataContract is unchanged relative to the initial revision. `master` is an intermediate ZK version and is excluded from the primary comparison.

The canonical History-Hiding contract set follows `test/benchmarks/HistoryHidingLifecycleRealProof.bench.js`: PoseidonT3, IncrementalBinaryTree, ZKIdentity and its constructor-created IdentityTree, AnonymousStakeRegistry, StateVerifier, PrivateStateTree, SlashingVerifier, AnonymousSlashing, the separate identity Verifier, PoseidonT4, AnonymousCtiAccess, AnonymousDisputeResolver, RatingVerifier, AnonymousRating, RewardVerifier and ShieldedRewardTree. There are 17 deployed contracts and 16 deployment transactions. The nested IdentityTree is counted and checked but its gas is included in ZKIdentity. ZKIdentity embeds identity-verifier code through inheritance, while AnonymousCtiAccess requires a separate verifier instance; both are actual canonical dependencies. StateTransitionVerifier and ZKDataContract belong to other flows and are excluded.

Canonical proof-bearing circuits are `identity`, `state`, `rating`, `slashing`, and `reward` under `circuits/build/artifacts/`. `state` is the canonical submission circuit; the smaller `state_transition` circuit is not substituted for it. Existing fixtures include the identity/stake/state paths and accountability commitments. The identity circuit intentionally does not constrain the supplied root to the reconstructed Merkle root; measurements describe that existing exception and do not assert sound identity membership. Benchmarks change no protocol contracts, circuits or security checks.

Both contract sets can use the same cached Solidity 0.8.20 compiler, optimizer enabled with 200 runs, viaIR false, EVM target Paris. Each contract's actual build information is recorded. Initialization is excluded from deployment totals; there is no deployment funding or testing-mode shortcut. Runtime sizes come from deployed code, including linked libraries and the nested tree.

Complete-architecture deployment gas is a valid cost comparison when both contract sets and their different features are explicit. Individual bytecode and gas rows are reported without forcing one-to-one equivalence across fundamentally different components. Shared infrastructure is counted once within each architecture. Runtime size alone does not establish every aspect of deployment compatibility.

The user confirmed that neither proof-of-concept implements actual off-chain CTI processing. Original baseline contracts also provide no standalone rating, anonymous membership proof, or shielded claim. There is therefore no matched off-chain CTI operation or baseline proof-generation metric to measure. These metrics remain unavailable, not zero. The new suite separately records original baseline operations using local `eth_call` simulation; these include ABI/provider/EVM overhead and are not an off-chain application client. Their semantics and fixtures differ from the canonical proofs. They cannot support a proof-overhead percentage. Groth16 witness generation, proving, combined time, serialization, proof size and complete-worker peak RSS are measured directly for all five canonical circuits. Compilation and trusted setup are excluded.

Existing `BENCHMARK_README.md` distinguishes legacy comparisons from canonical production-proof results. Existing JSON/CSV datasets, including `benchmark-results/history-hiding/`, remain untouched. The new runner writes exclusively to a new directory under `benchmark-results/comparative/`, refuses overwrites and records preservation hashes. Regression benchmarks run in a temporary copy to preserve their normal output definitions while protecting the original datasets.
